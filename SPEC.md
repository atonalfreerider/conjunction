# Conjunction — product and engineering spec

Working name **Conjunction** (in astrology, a conjunction is two bodies meeting in the same part of the
sky; here, two people meeting in the same place). Tagline: *"Your stars, nearby."* The name is a
placeholder until the owner picks one from `docs/NAMES.md`; keep it in one place per platform
(Android `strings.xml` `app_name`, iOS `CFBundleDisplayName`) so it is easy to change.

- Android application id / iOS bundle id: `com.metavirtuoso.conjunction`
- Publisher: MetaVirtuoso (same accounts as the Sundial app on this PC)
- Ages 18+ only (proximity features connect strangers).

## Features

1. **Birth chart.** Input: birth date, exact birth time (hour + minute; "unknown time" allowed but
   disables Ascendant/houses/hour pillar), birth place (geocoded on device to lat/lon + IANA time zone
   valid *at the birth date*, so historical DST is right). Output: Sun, Moon, Mercury–Pluto, Ascendant,
   Midheaven, Whole-sign houses (default) with sign, degree and house; major aspects (conjunction,
   sextile, square, trine, opposition with standard orbs). Drawn as a stylized chart wheel.
2. **Horoscopes, written on the phone.** Daily reading plus "natal reading" sections, generated by the
   phone's on-device model: Android = Gemini Nano via ML Kit GenAI Prompt API
   (`com.google.mlkit:genai-prompt`), iOS = Apple Foundation Models (`LanguageModelSession`). Same
   pattern as `~/Desktop/SUNDIAL` (`HoroscopeGenerator.kt`, `HoroscopeService.swift`): availability
   check, download progress, entertainment-only guardrails in the prompt, clean-up of the answer.
   When the on-device model is unavailable, fall back to a deterministic template reading assembled
   from bundled text fragments (never a cloud LLM — readings never leave the phone).
3. **Chinese zodiac + blood type.** Year animal and element (sexagenary year, boundary at Lichun
   ~Feb 4, with the lunar-new-year animal also shown), plus the Four Pillars (BaZi: year, month, day,
   hour pillars) from the exact birth time. Blood type (A, B, AB, O, plus Rh +/−, optional) for the
   East-Asian blood-type personality reading (ketsueki-gata). Combined "Eastern reading" generated
   on device like (2).
4. **Palm reading.** Camera capture (or photo pick) of the open palm, guided by an overlay. On device:
   hand-pose / landmark detection (iOS Vision `VNDetectHumanHandPoseRequest` + contour detection;
   Android ML Kit / MediaPipe Hand Landmarker + edge analysis) to measure hand shape and the heart,
   head, life and fate lines; code turns measurements into a typed `PalmFeatures` description, and the
   on-device model writes the reading from it. On Android, if Gemini Nano accepts image input on the
   device, also pass the image. The palm photo is never uploaded and is deleted after the reading
   unless the user saves it.
5. **Nearby compatibility ("Conjunctions").** Opt-in only, off by default, toggled from a clear
   "Nearby" switch with a plain-language explanation. When on (and the app has foreground location;
   Android runs a `location`-type foreground service with a persistent notification, iOS uses
   When-In-Use location with background updates started in the foreground and the blue indicator),
   the phone reports a coarse position to the backend every ~60 s or 25 m of movement. The backend
   finds other opted-in users within **~50 m**, computes compatibility, and sends both a push
   notification ("A Leo ☌ is nearby — 87% compatible"). **Exact location is never shown to the other
   user** and is never stored in history; the server keeps only the latest position with a short TTL
   (10 min). Distance shown only as "nearby".
   - Compatibility = deterministic synastry score from both charts (sun/moon/venus/mars/ascendant
     aspects, element and modality balance) blended with Chinese zodiac compatibility (trines, clashes,
     secret friends) and blood-type pairing. Code, not an LLM, computes the number; the explanatory
     blurb on each phone is written on device.
   - **Birthday twins** (same birth date; "exact twins" if also same birth hour) get a special,
     distinct full-screen celebratory popup and notification.
   - Each side can tap **Connect**. Only when *both* connect do they become friends: each then sees
     the other's profile photo, display name, first line of bio and big-three signs, and can send a
     short intro message. Before that, the other side sees only signs + compatibility, no photo, no
     name.
   - Safety: block, report, "pause nearby for 1 h / until tomorrow", snooze per person, rate limits,
     18+ age gate, no messaging before mutual connect, intro messages are moderated server-side.
6. **Profile.** Display name, profile photo (moderated, stored in backend storage, only served to
   mutual friends), short bio, birth data (birth data stays on device; only derived chart summary —
   signs/degrees needed for compatibility, birth date for twins check — is uploaded when Nearby is on).
7. **Onboarding:** age gate (18+), legal waiver + terms + privacy acceptance (versioned, stored),
   birth data entry, optional blood type, optional Nearby opt-in, notifications permission.

## Look and feel — heavily stylized

Art direction **"Celestial Art Nouveau"**: deep midnight indigo (#0B0A2A) and ink-violet grounds,
burnished gold leaf (#D4AF37 → #F5E6A8 gradients), rose-copper accents (#C97B63), moonstone pearl
text (#EDE6F7). Ornate Mucha-style frames, filigree borders, constellation line-work, starfield
parallax, subtle grain. Display typeface: an OFL decorative serif (e.g. "Cinzel Decorative" /
"Cormorant" — bundle the OFL font files and license); body: "Cormorant Garamond" or "EB Garamond".
Motion: slow shimmer on gold, orbiting glyphs, chart wheel that draws itself, card flips for readings.
Both platforms must look like the same app.

## Shared engine contract (Kotlin `android/core` and Swift `ios/Sources/ConjunctionCore` must agree)

Both engines implement the same functions with the same results (shared golden test vectors in
`testdata/golden_charts.json`; both test suites read it). Angles in degrees, longitudes tropical,
geocentric, ecliptic of date. Accuracy target: planets within 0.05° of Swiss Ephemeris for 1900–2100
(use VSOP87-truncated / Meeus algorithms; Moon via Meeus ch. 47; Pluto via Meeus ch. 37), Ascendant
and MC within 0.1°.

- `BirthData(date: LocalDate, time: LocalTime?, latitude, longitude, zoneId: String, placeName)`
- `NatalChart.compute(birth) -> NatalChart { bodies: [Body(name, longitude, sign, degreeInSign,
  retrograde, house?)], ascendant?, midheaven?, houses?: [12 cusp longitudes], aspects: [Aspect(a, b,
  type, orb, applying)] }`
- `ChineseZodiac.compute(birth) -> { yearAnimal, yearElement, yinYang, lunarYearAnimal,
  pillars: { year, month, day, hour? } each = (heavenlyStem, earthlyBranch) }`
- `BloodType { A, B, AB, O }`, `BloodTypeReading.traits(type)`
- `Compatibility.score(a: CompatProfile, b: CompatProfile) -> { total 0..100, western, chinese,
  blood, highlights: [String] }` where `CompatProfile` = the uploaded summary (sun, moon, venus, mars,
  ascendant? longitudes, chinese year animal + day-pillar stem, blood type?, birthDate,
  birthHour?). `isBirthdayTwin`, `isExactTwin`.
- `PalmFeatures { handShape(earth/air/fire/water), lineLengths/curvature/depth per line,
  fingerRatios, mounts }` → `PalmReadingPrompt.build(features)`.
- `HoroscopePrompt.daily(chart, transitsNow, date)`, `.natal(chart, section)`, `.eastern(...)`,
  `.compatibility(a, b, score)` — prompt strings with identical wording on both platforms.

The **backend** re-implements only `Compatibility.score` (TypeScript) and must match the same
golden vectors (`testdata/golden_compat.json`).

## Backend (Firebase)

- Auth: Firebase Anonymous Auth upgraded with Sign in with Apple / Google (optional); every call
  authenticated.
- Firestore: `users/{uid}` (public-to-friends profile, compat summary, settings),
  `presence/{uid}` (geohash-7, lat, lon, updatedAt, expiresAt TTL 10 min — readable by no client),
  `encounters/{pairId}` (uids, score, twin flags, connectA/B, createdAt), `friends/{uid}/list/{other}`,
  `messages/{pairId}/msgs`, `blocks/{uid}/list/{other}`, `reports/{id}`.
- Callable functions: `updatePresence` (rate-limited; finds neighbours in same + adjacent geohash-7
  cells, haversine ≤ 50 m, skips blocked/paused/snoozed/already-seen-in-24h pairs, writes encounter,
  sends FCM to both), `connect(encounterId)`, `sendIntro(pairId, text)`, `block`, `report`,
  `deleteAccount` (full erasure), `exportData`.
- FCM for push to both platforms (APNs via FCM).
- **TypeSafe (Jev)** server-side only, key from Firebase secret `TYPESAFE_API_KEY` (never in apps):
  moderation of user text that strangers see — intro messages, bios, display names — with Noul
  questions (harassment, sexual content, solicitation/scam, personal contact info / off-platform
  lure, hate) and a Choice router for incoming reports (urgency / category). Code owns the policy
  thresholds; uncertain cases are held for human review. Read https://docs.typesafe.ai/llms.txt.
- Profile photos: Storage `profilePhotos/{uid}.jpg`, readable only via a function that checks the
  friendship; image moderation by Cloud Vision SafeSearch (or held until reviewed).
